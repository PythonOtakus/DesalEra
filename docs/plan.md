# 开发计划

> 目标：把《淡化器纪元》从策划文档推进到可验证的垂直切片。
>
> 本文档只写"接下来做什么"和"怎么算做完"。已完成的工作见 `progress.md`，技术与竞品事实见 `research.md` 第三部分。

## 0.0 方向修正：不做固定视角 SLG（2026-10-03）

原型原本按固定俯视相机 + 光标放置建造来做，交付后判定**手感是 SLG，不是 3A 动作生存**。
固定偏移相机 `(0,11,-12)` 加 LookAt 是根本原因：角色永远只能被俯视，构图永远不变。

已改为第三人称环绕相机（右键转视角、滚轮缩放、偏肩偏移），移动带加减速。
这一条改变了后续排期的优先级：

| 优先级 | 项 | 理由 |
|---|---|---|
| 立刻 | **世界碰撞体** | 没有碰撞体，相机的遮挡拉近不生效，角色也不会被木筏挡住。这是所有"3A 手感"的前置条件 |
| 高 | **攀爬 / 绳索移动** | 梯子与绳索的 6 个 clip 早已烘焙接进动画图却无处可用。支撑柱天然就是可攀爬物，这是现成的 3A 移动语汇 |
| 高 | **垂直移动动词**（跳、翻越） | 当前高度由 `SurfaceHeight()` 直接赋值，没有重力。这是"角色感"和"物体感"的分界 |
| 中 | 建造反馈（幽灵预览、吸附、非法原因） | 网格放置本身可以保留，它不是 SLG 的问题，相机才是 |
| 低 | 生存压力重做（P0-2） | 风险登记里标"高"，但方向没定之前调数值会白调 |

网格建造**不废弃**。它是这个产品的差异化系统和第一大 USP，废弃它等于放弃产品。
要改的是视角、手感和移动语汇，不是把建造变成动作游戏。

## 0. 当前判断

**能做，但必须缩小。** 策划案描述的是 4-7 年、150-300 人、2-4 亿美元量级的产品（四大系统 + 四层海域 + 8 人联机 + 联盟 MMO + 赛季 GVG + 舰队海战），而其 2.7 节的排期是 18 个月。这个矛盾必须在开工前解决，否则所有排期都无意义。

**已验证的部分**：
- 竖向承重、浮力、倾覆、连锁坍塌（重力流模型）
- **三维交叉支撑**（直接刚度法，2026-10-02 完成）—— 第一大 USP 技术上成立
- 拉压分离强度判据，衍生出材质化的设计空间

**未验证且风险最高的部分**：硬核生存的失败与恢复机制。这是策划案最大的设计空洞，也是 P0-2。

**模型边界**：当前为纯轴力桁架模型，不含弯曲刚度。单跨布局下斜撑收益偏低（15%），多跨布局预期更高。详见 P1-4。

## 1. 范围决策（需你确认）

以下四项需要你拍板，我给出建议和代价。

### 1.1 v1 是否单人

**建议：v1 单人，多人移入上市后路线图。**

- 代价：推迟了"社交"这个 PC 端核心卖点，8 人联机不是加功能而是重写所有系统的状态模型
- 收益：范围减少约 40%，且单人版本的风险已经可控
- 依据：Subnautica 全程无多人，且其"孤独"是设计前提而非未完成项

### 1.2 SLG / 赛季 / 舰队海战是否进 v1

**建议：全部移出，用 v1 留存数据决定是否做。**

- 代价：失去"成熟后期玩法"这个差异化卖点
- 收益：避免为不确定的内容预付生产成本
- 依据：这些系统需要 live-ops 团队和足够在线人数支撑，v1 阶段两者都不具备

### 1.3 材料比强度的取舍（见 research.md 3.3）

**建议：接受当前取舍，把材料设计成有明确代价的选项。**

- 钢材：密度大但绝对强度高 → 适合需要承载但不能太重的构件
- 混凝土：比强度最优但很重 → 适合水下基础和压舱
- 木材：轻且便宜 → 适合上层建筑

这比"材料严格递增"更有玩法深度。风险是需要 UI 明确表达，否则玩家会觉得被坑。

### 1.4 美术方向（漫画感 vs 风格化写实）

**建议：先做 A/B 样片盲测，再定管线。**

- 需要：同一场景两种风格各出 1 张样片，找 20 个目标用户盲测投票
- 约束：12 GB VRAM 偏紧，风格化路线更现实
- 代价：约 1-2 周

## 2. 任务列表

优先级 P0 = 阻塞其他任务，P1 = v1 必备，P2 = 时间允许。

### P0-1 三维交叉支撑验证 ✅ 已完成（2026-10-02）

**为什么第一**：如果斜撑系统不成立，2.1.5 节的第一大 USP 就不成立。这是 kill-or-live 级风险。

**结果**：成立。`TrussSolver`（直接刚度法）验证 8 层框架 X 撑可将顶部位移降至无支撑的 85%，且斜撑刚度提升 40 倍时位移降至 47%。同时发现拉压承载力分离，衍生出"X 撑 vs 拉杆"的材质设计空间。详见 `research.md` 3.5。

**遗留**：纯轴力模型未含弯曲刚度（EI），单跨侧移偏大。见 P1-4。

### P0-2 失败与恢复机制

**为什么第二**：这是策划案最大的设计空洞。所有系统都在"积累"，但没定义"失去"。硬核生存玩家要的是真实风险，缺少恢复循环会让硬核变成劝退。

**做什么**：定义构件失效后的后果与恢复路径。参照现实：局部坍塌 vs 连锁倾覆 vs 全域沉没，三种损失等级。

**验收标准**：
- 明确区分"损坏可修复"、"局部坍塌"、"基地沉没"三档
- 每档有明确的资源损失与恢复成本
- 存在"主动拆除回收材料"的机制（策划案 2.4.1 提到但未定义）
- 坍塌不能导致存档损坏或不可恢复死锁

**当前状态**：未开始。`TrussReport.FirstFailedMember` 与 `FailedMembers` 已提供判定基础，但尚无后果层。

### P1-4 刚架模型（弯曲刚度）

**为什么需要**：`TrussSolver` 是纯轴力模型，单跨框架的侧移主要由立柱弯曲贡献，模型无法表达，导致 X 撑只改善 15%，低于真实桁架水平。

**做什么**：在单元刚度矩阵中加入弯曲项（EI/L 和 12EI/L³），把模型从桁架扩展为刚架。

**验收标准**：
- 单跨 X 撑的改善幅度达到 50% 以上
- 无支撑框架能正确表现为柔性，而非刚性不变形
- 矩形截面构件的平面内与平面外刚度不同（当前平面外恒为无穷大，是错的）
- 现有 52 个测试全部不回归

**替代方案**：若实现成本过高，改为多跨夹具验证（多跨框架的斜撑收益应显著更大），并在设计上明确"基地以多跨网格为主，单跨仅用于小型附属结构"。

**当前状态**：未开始

### P1-1 生存指标系统

**做什么**：饥饿、口渴、健康、体力、士气五项指标，含环境联动与疾病系统。

**验收标准**：
- 五项指标相互联动，任一归零产生连锁后果
- 天气/深度/时段对消耗速率有实际影响
- 可在不开编辑器的情况下跑 24 小时模拟，验证不会数值崩坏
- ≥ 10 个测试覆盖联动与极端情况

**注意**：必须能在 headless 下跑长时模拟，否则调平衡会非常痛苦。

### P1-2 建造交互原型

**做什么**：放置预览、承重预检、非法放置拦截、拆除回收。用 real 资产，不做美术。

**验收标准**：
- 放置前能显示该位置的承重/重心预判
- 非法放置被拦截且给出原因
- 拆除能回收部分材料
- 全流程键盘鼠标可完成，不需要精确像素操作

### P1-3 领域文档

**做什么**：写清建造系统的玩家可见规则（什么是承重、为什么会塌、怎么防）。

**验收标准**：
- 一个没读过代码的人读完能预测自己建造的结果
- 规则描述与求解器实际行为一致（用测试固定）

### P2-1 美术方向 A/B

见 1.4。

### P2-2 垂直切片

前三项完成后，组装成一个 15-20 分钟的完整循环：建筏架 → 装生产建筑 → 下潜采集 → 遭遇一次灾害 → 损失与恢复。

**验收标准**：
- 有存档/读档
- 有一处真实失败和一处真实恢复
- 能在目标分辨率下稳定 60 FPS
