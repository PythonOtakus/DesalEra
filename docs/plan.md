# 开发计划

> 目标：把《狂涛纪元》从策划文档推进到可验证的垂直切片。
>
> 本文档只写"接下来做什么"和"怎么算做完"。已完成的工作见 `progress.md`，技术与竞品事实见 `research.md` 第三部分。

## 0. 当前判断

**能做，但必须缩小。** 策划案描述的是 4-7 年、150-300 人、2-4 亿美元量级的产品（四大系统 + 四层海域 + 8 人联机 + 联盟 MMO + 赛季 GVG + 舰队海战），而其 2.7 节的排期是 18 个月。这个矛盾必须在开工前解决，否则所有排期都无意义。

**已验证的部分**：立体建造的承重/浮力/倾覆/坍塌模型可行，纯 C# 实现，36 个测试通过，无需自研物理引擎。

**未验证且风险最高的部分**：三维交叉支撑。这是第一大 USP 的真正难点，当前原型只有"竖柱 + 悬臂板"。

## 1. 范围决策（需你确认）

以下四项需要你拍板，我给出建议和代价。

### 1.1 v1 是否单人

**建议：v1 单人，多人移入上市后路线图。**

- 代价：推迟了"社交"这个 PC 端核心卖点，8 人联机不是加功能而是重写所有系统的状态模型
- 收益：范围减少约 40%，且单人版本的风险已经可控
- 依据：Subnautica 全程无多人，且其"孤独"是设计前提而非未完成项

### 1.2 SLG / 赛季 / 舰队海战是否进 v1

**建议：全部移出，用 v1 留存数据决定是否做。**

- 代价：失去"成熟后期玩法"这个差异化卖点
- 收益：避免为不确定的内容预付生产成本
- 依据：这些系统需要 live-ops 团队和足够在线人数支撑，v1 阶段两者都不具备

### 1.3 材料比强度的取舍（见 research.md 3.3）

**建议：接受当前取舍，把材料设计成有明确代价的选项。**

- 钢材：密度大但绝对强度高 → 适合需要承载但不能太重的构件
- 混凝土：比强度最优但很重 → 适合水下基础和压舱
- 木材：轻且便宜 → 适合上层建筑

这比"材料严格递增"更有玩法深度。风险是需要 UI 明确表达，否则玩家会觉得被坑。

### 1.4 美术方向（漫画感 vs 风格化写实）

**建议：先做 A/B 样片盲测，再定管线。**

- 需要：同一场景两种风格各出 1 张样片，找 20 个目标用户盲测投票
- 约束：12 GB VRAM 偏紧，风格化路线更现实
- 代价：约 1-2 周

## 2. 任务列表

优先级 P0 = 阻塞其他任务，P1 = v1 必备，P2 = 时间允许。

### P0-1 三维交叉支撑验证

**为什么第一**：如果斜撑系统不成立，2.1.5 节的第一大 USP 就不成立。这是 kill-or-live 级风险。

**做什么**：扩展求解器，支持 X 形斜撑、水平桁架、斜拉索。构造一个受侧向风荷载的塔架，验证侧向刚度与失稳模式。

**验收标准**：
- 斜撑能显著降低侧向变形（相比无支撑的悬臂板，位移下降 > 50%）
- 能复现"加一根斜撑比加粗立柱更有效"这个设计直觉
- 失稳时能指出是哪根构件先失效，而不是整体随机崩塌
- 新增 ≥ 8 个测试覆盖侧向荷载

**当前状态**：未开始

### P0-2 失败与恢复机制

**为什么第二**：这是策划案最大的设计空洞。所有系统都在"积累"，但没定义"失去"。硬核生存玩家要的是真实风险，缺少恢复循环会让硬核变成劝退。

**做什么**：定义构件失效后的后果与恢复路径。参照现实：局部坍塌 vs 连锁倾覆 vs 全域沉没，三种损失等级。

**验收标准**：
- 明确区分"损坏可修复"、"局部坍塌"、"基地沉没"三档
- 每档有明确的资源损失与恢复成本
- 存在"主动拆除回收材料"的机制（策划案 2.4.1 提到但未定义）
- 坍塌不能导致存档损坏或不可恢复死锁

**当前状态**：未开始

### P1-1 生存指标系统

**做什么**：饥饿、口渴、健康、体力、士气五项指标，含环境联动与疾病系统。

**验收标准**：
- 五项指标相互联动，任一归零产生连锁后果
- 天气/深度/时段对消耗速率有实际影响
- 可在不开编辑器的情况下跑 24 小时模拟，验证不会数值崩坏
- ≥ 10 个测试覆盖联动与极端情况

**注意**：必须能在 headless 下跑长时模拟，否则调平衡会非常痛苦。

### P1-2 建造交互原型

**做什么**：放置预览、承重预检、非法放置拦截、拆除回收。用 real 资产，不做美术。

**验收标准**：
- 放置前能显示该位置的承重/重心预判
- 非法放置被拦截且给出原因
- 拆除能回收部分材料
- 全流程键盘鼠标可完成，不需要精确像素操作

### P1-3 领域文档

**做什么**：写清建造系统的玩家可见规则（什么是承重、为什么会塌、怎么防）。

**验收标准**：
- 一个没读过代码的人读完能预测自己建造的结果
- 规则描述与求解器实际行为一致（用测试固定）

### P2-1 美术方向 A/B

见 1.4。

### P2-2 垂直切片

前三项完成后，组装成一个 15-20 分钟的完整循环：建筏架 → 装生产建筑 → 下潜采集 → 遭遇一次灾害 → 损失与恢复。

**验收标准**：
- 有存档/读档
- 有一处真实失败和一处真实恢复
- 能在目标分辨率下稳定 60 FPS

## 3. 明确不做（v1）

| 项 | 理由 |
|---|---|
| 多人联机 | 重写所有系统状态模型，等单人验证后决策 |
| 联盟 / 赛季 / GVG | 需要 live-ops 和在线人数支撑 |
| 舰队海战 | 依赖 SLG 框架 |
| 四层海域 | 先做浅海 + 中层，深海验证建造稳定性后再开 |
| 破坏表演（碎裂/掉落） | 求解器只判定失效，表演是美术问题 |
| 配音 | 成本高，核心循环未验证前不值得投入 |
